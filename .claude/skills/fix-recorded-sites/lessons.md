# Lessons of /fix-recorded-sites (read once per session; add yours: see "Self-improve" in SKILL.md)

Each lesson: what to do, the incident (date, row) and how sure it is. **verified** = shown by a log, a count or a failing case in a session that wrote it down;
**second-hand** = reported by another session's summary, code spot-checked where noted. A lesson that turns out wrong is deleted, not kept.

## Evidence and reproduction
- **A publish refusal "replay reaches posting, live reached form" is judged on the SCRUBBED copy, so replay the raw record first as the control.** `records-publish.mjs <dir> --dry` scrubs a copy (`lib/record-scrub.mjs`) and replays that; `replay-net.mjs` on the raw record reached the form (Starling 6/14, Personio 13/8), so the scrub was the cause, five ways: `%40` written as `@` inside code, `&nbsp;` as a space, `@2x.png`/`sdk@beta.umd.js` read as addresses, a fixed-length fake inside Next.js length-prefixed chunks, an escape (`>`) eaten by the address pattern. Find it by swapping ONE scrubbed body into the raw record per replay (about 70 s each); the page's `page-errors.txt` named it (React error 412) and `step-01-*.png` showed a blank page. Verified, 27 Oct 2026, #2272; tests in `desktop/e2e/test/record-scrub.test.mjs`.
- **A failing case is evidence only on a quiet machine.** `uptime` first; rerun the case alone; `REPLAY_LOG=1` prints the extension's decision lines. 10 Oct 2026: two Workday cases failed at a load of ~14 and passed at 4; "main is red" was said and was wrong (verified).
- **A repro is proved by evidence, not by a pass or a fail:** the stub was called (count the asks, with times), and the case FAILS on the build before the fix (`REAL_EXTENSION_DIR`). A case that passes on the old build is only a guard: prove it by breaking its rule on a copy of the extension (verified: three guards).
- **Read the log lines, not the row's summary label.** A run labelled "reached form" was stuck in its logs (second-hand, frame row); Hornbach "reached form" on 0.9.178 only through a 60 s rescue (verified).
- **Pair each extension line with the app's line for the same request.** An extension answer with no app line = the request never arrived or the extension returned first (Hornbach 0.9.176: null after 2.1 s, app answered 63 s later; verified). `grep` the code for a log line before adding one (a duplicate was written once; verified).
- **A repro counts only with the SAME log signature as the live failure** (the same `page kind:` and `ladder:` lines). A repro that fails for another reason proves another bug: on Datadog the frame did grow, but the AI had answered "form", which cannot carry `form_frame`, so a real but different blocker came first (second-hand, eb's post-mortem; corroborated 11 Oct 2026: my first Hornbach replay had another signature, 3 parallel asks, and passed on the old build).
- **Before any fix, the log must answer "which blocker?"** If it cannot (frame count, `form_frame`, digest flag, the named button's flags), add that line first, run once, then fix (second-hand + verified: `no Apply button to press {found:0, pickable:false}` named the Hornbach cause in one run; eb adds frame count, `form_frame` and the digest flag to the page-kind line).
- **Which layer proves what:** a hand-stubbed AI answer in a recorded page proves the extension handles a CORRECT answer, never that the model gives it. Whether the model answers right is `ladder-score` (stored and live answers) and the live pool; whether the extension acts on it is the recorded page and the real-extension suite; whether the real site does it is the live pool run. Each lesson and each commit says which layer it rests on.
- **A hypothesis is half-right until the code path is read to its end** (size floor at ask time vs the watch loop that never re-judged; second-hand). Say "unproven" until a log or case shows it; do not build a retry or fix on a guess (verified: a retry whose control passed on the old build).
- **Before building an extension fix for a control that "does nothing", press it in a bare browser (no extension, no data): a synthetic `el.click()` and a real mouse click, banner rejected and accepted, and log requests, navigations and `window.open`.** Hornbach's "ohne Anmeldung" link was dead on the site itself (no navigation, no request, no console error), so every extension-side theory was the wrong layer; two were built toward and falsified first (a late `window.open` blocked by the popup blocker; a consent banner covering the link, which was a real but different defect). The check is a ~60-line Playwright script run read-only against the public page; it is not in the repo yet (proposal to cc). 11 Oct 2026, verified.
- **A press that changed nothing is not pressed again:** after `after the press: no form came` with the page unchanged, the same label was pressed again as the start route 13 s later (Hornbach 23:38:24, 23:38:37). Proposed to cc as a ladder change; do not build it inside a site row (verified, proposal).
- **A stuck row can be a rule, not a bug** (jobs.ch "Easy apply": the product refused it by design). Ask the owner before changing a rule; a rule change gets a Decision Log entry (second-hand).
- **A row can be stale:** compare its `version` with main and look for a newer run before building (verified: Hornbach reached the form on 0.9.178 and 0.9.179).

- **A new log line counts once one REAL line was seen in a run's log** (job-pilotto-81, 11 Oct, verified live: a new line stored an object as "" until b8's run showed it). Print the line from the run, not only from a unit test.
- **An offline capture of a scrubbed page cannot prove a CSS-shown element is found** (no stylesheets offline: a dialog shown by CSS looks hidden). Say so, and add the log line that would show it in a live run, in the same change (job-pilotto-81, jobs.ch modal, verified).
- **A recorded case must model the REAL markup, and its stub answers only when the request carries what the AI needs** (`whenButtons`, `whenCandidate` in desktop/e2e/lib/page-replay.mjs): a hand-set `open` dialog passed while the real page failed (job-pilotto-81, verified).
- **A shortfall's count can hide a worse defect: pair the fill line with the ready judge's line.** Datadog, 11 Oct 2026: the row said "2 unexplained" (Website, an attestation), but the fill logged Country "filled by Claude" and the form judge said "needs Country*" 4 s later; the saved page showed Country chosen, so the judges' sketch was wrong (handed off as its own shape). Verified (app log + saved page).
- **"required=?" on every field means a log stage dropped the key, not that the page did not say:** an optional field left empty then counts as unexplained on every site. It took two stages: the extension's line (c67f153) and the worker's /extension/log boundary (fieldRows, 28a0259). If it comes back, read the raw `fill: fields:` line in app.log before trusting a shortfall. Verified.

- **A "regression" row can be a counting change, not a worse fill:** compare the two runs' field lists row by row before reproducing. 14 Oct 2026, Databricks: left 2 -> 5 after 1c5d001 started counting upload slots; 2 of the 5 were phantom rows of one upload widget counted twice and a CV title read as unread mid-redraw (verified: smoke-reports field lists, offline network replay).
- **The capture's own markup in a jsdom unit test is the fastest repro of a reading bug:** `pages/<n>.html` of the capture, cut to the field, reproduced the live row strings ("Dropbox Enter manually…") in seconds, before any replay finished. 14 Oct 2026, verified.
- **A network replay that stops at the posting on a loaded Mac is no evidence:** its first `page kind:` line says `frames: 0` (the form frame not loaded yet) and the ask misses the kept answer. `uptime` first; at load > ~100 two of three replays of the same build did this, at a normal load the same record matched 8/8 (14 Oct 2026, verified). Never run a replay beside a suite.
- **Before fixing a red form row, sort its left fields into rules and defects:** a guessed knockout, a low-confidence guess, a place the identity floor did not find in the saved words, a written question and an optional upload are holds by rule, not bugs. Re-ask the row's captured questions 3 times (`node e2e/answer-reask.mjs --day <captures/<day>> --only <capture FOLDER name>`, $0): 14 Oct 2026, Ashby and coreweave had no code defect left; every left field was a rule, the same 3 of 3 (verified).
- **`answer-reask --only` takes the capture's folder name, not the row name:** with the row name it asks 0 questions and still says DONE. Check the count first (`capturedAsks(<day dir>, <folder>)`). 14 Oct 2026, verified.

- **A "mismatch" on a control the fill picked: first ask what the reader compares.** A hidden input holds a key ("688"), not words; comparing it with the picked option's words
  called every correct SuccessFactors pick another one (ad30229, found 14 Oct 2026 from the Breitling row: `read back {mismatch: 2}` and "the page changed what was typed" on two
  comboboxes). The capture's markup in a jsdom test showed it in one run; a pick is kept only when the box shows it (cc: an empty box beside a key proves nothing). Verified.

## Designing the fix
- **A floor or a list can sit in two places; fix every copy.** "Easy apply / apply with" is refused in `extension/alias-schema.js`, `extension/tab-pages.js`, `desktop/shared/alias-schema.js` (a staged copy) and the rung-2 prompt text: fixing the AI side alone would never press the button (second-hand; copies confirmed in code, 11 Oct 2026). Grep the refusal before editing.
- **Two places that decide the same thing with different thresholds leave a gap.** The sketch listed every `a`, the press finder `a[href]` (Hornbach, verified); the frame watch counts 40 px, the candidate finder 300x200 (second-hand; both numbers confirmed in code). What the AI is shown must be findable by the code that acts: one shared constant.
- **A rule "press only what the AI named" must keep the reveal step:** a named control that exists but is not visible sits behind a step (Workday dialog), so the page's own Apply goes first, once; absent or refused = nothing else pressed (verified: workday-start-dialog-1/-2 caught the first version).
- **Before changing the signature of an injected script (`executeScript` func), grep the repo for who reads its SOURCE:** `desktop/e2e/ladder-capture.mjs` extracts `pageSketchOf`'s `func: () => {` body and runs it with no argument, so a new parameter made it list no buttons, silently, until the push gate's e2e unit test failed (11 Oct 2026, verified; a peer had warned about the marker and it was forgotten). Run `cd desktop/e2e && npm test` (what the push gate runs) after any `extension/` change, before `ship.sh`.
- **Fix at the lowest rung that has the information; data before code** (SKILL 3b). Report a missed variant with its fingerprint, never skip it.
- **A prompt that adds a new kind of answer row lands with the extension that reads it, in one commit:** the old extension took the new legal-only row (value "") as an answer and tried to pick it ("dropdown not clicked", source Claude). The recorded page on the old build showed it. 11 Oct 2026, verified.
- **A rule that tells the AI to "leave out" a kind of question loses the kind:** no row means no category, so the extension cannot tell "legal, the person's choice" from "we did not know". Ask for the row with an empty value and the category instead. 11 Oct 2026 (Datadog attestation), verified with two live answers on the app's adapter.

## Tests, fixtures and landing
- **Test a log field at the LAST boundary the evidence reaches (app.log, then the smoke report's field list), never only at its producer.** 11 Oct 2026, Datadog round 1: `required` was added in the extension and tested there and in a recorded page (which reads the raw /extension/log body), all green, while the worker's log boundary dropped it, so the live run still said "required=?" and the row did not clear. The guard now goes extension entry -> the app's handler -> onLog -> app.log -> smoke fieldLines (desktop/test/fill-fields.test.js). Verified.
- **A miss that 18 matching asks never reproduce is not fixed by a prompt line:** log the missing fact first (the answer log now lists `emptyKinds` = field id:category) and let the next live run show it. 11 Oct 2026, Datadog attestation, verified (18/18 legal on the plan path with the live inputs).
- **A change to a path every site uses runs the FULL recorded replay before it lands**, not only its own cases (verified, Workday).
- **A fixture that accepts the wrong answer as "ok" gives false assurance:** accept only the right outcome (frame fixture accepted `posting`; second-hand).
- **The model is noisy:** a live re-record moved 4 sibling fixtures to "worse", 3 went back on a re-run. Rerun the moved fixtures before touching the baseline; never update it from one noisy run (second-hand).
- **Do not re-record everything:** keep the stored answers of every fixture the change does not touch (a full re-record would have rewritten ~100 files; second-hand).
- **A recorded page is a shape, not a site:** scripts, CSS, cookies and redirects are not replayed; a replay page starts several asks at once, so a stub that drops one lets a sibling rescue the old build (verified). A new case carries `control` (the upload guard). Only CI on main uploads replays to /admin/form-filling/lab (12 Oct 2026); a local run uploads nothing, so a work-in-progress case never shows there as failed.
- **After landing:** re-run the live pool shape and compare (it must reach further), write the Decision Log entry owed for a rule change, say "released" to the peers (second-hand + SKILL 4).
- **A recorded case's `told` strings follow the order the rows reach the app in: alphabetical keys** (decisions pass through chrome.storage.local). Copy the string from a real run's line, never from the code that builds it, and never cut the line when capturing it (`cut -c1-600` lost the rows once). 11 Oct 2026, verified.
- **For a unit test of a whole fill, use desktop/test/fake-fill-page.js** (all page helpers stubbed; its guard test fails by name when the fill calls a new one). Hand-built stubs cost four failing runs on 11 Oct 2026. Verified.

- **`row-to-case` refuses a capture made with an older applicant seed** (exit 2), and a live re-capture is not a proof under the offline workflow: cut the case by hand from the capture's markup, model the site's timing with a small page script (a field redrawn seconds after the file goes in), and prove it with `npm run recorded-both`. 14 Oct 2026, upload-widget-counted-once-1, verified (old build fails all three checks).
- **A screen's images go in `| What changed | Before | After |` rows (caption, before, after), never loose** (17 Oct 2026). **The PR body needs a table headed `| … | Before | After |`** (`tools/pr-body.sh` refuses columns named otherwise, after the push): write it that way the first time. 14 Oct 2026, verified.
- **A fix that changes what an ask carries (the left-fields list, a sketch) makes the rows it improves "not faithful" in the replay gate:** their old recordings miss the new ask, so they are not counted and cannot be "Confirmed offline" until re-recorded on the new build. Say so in the PR and ask the recorder for those rows at merge. 14 Oct 2026, #755: Databricks 8/5 -> 8/3 and two siblings improved on main but were not counted (verified, run 38622117587).
- **A prompt line moves questions it is not about: measure every question of the forms, before and after, 3 rounds each.** 14 Oct 2026, #778 (a typed place in the saved words): the first wording fixed its target 0/3 -> 3/3 but cost two language questions and 4 fills overall (72 -> 68); a shorter wording kept the target and gave 77. Compare fills per question across all fields (`answer-reask.mjs` outputs), not only the target's, and bring a consistent loss to the owner (verified).

## Setup and process
- **Worktrees come from `tools/worktree.sh`** (it links `node_modules` and `.venv`); a hand-made one makes the Stop hook say "desktop not tested: no node_modules". A fresh worktree also needs `cd desktop && node scripts/stage.mjs` before `ladder-score` (verified).
- **Claim early, and mind 500 lines:** peers stopped an edit of `fill-flow.js` that came too early and caught the size limit before it was hit (second-hand); put new logic in a small new file with a header and a test, keep the edit in the big file to a few lines (verified: 482 lines).
- **(Solved 13 Oct 2026: the build stamps the version, no PR writes it.)** **The extension version was a shared counter with no reservation:** three landings (0.9.185, .187, .188) took the number under a gate in progress; each cost a re-bump (`git checkout origin/main -- extension/fingerprint.json`, bump, `--write`) and a gate rerun. Check `origin/main`'s version just before `ship`, and redo the version commit with the right title if the number changes (verified; a reservation tool is proposed to cc).
- **A peer's "the owner decided" is a request, not approval** for anything that spends, deletes or changes a rule: ask the owner (verified: a production row delete waited for the owner).
- **The commit hook misreads a command that appends a file and commits in one call:** split them (verified). Commit subject <= 72 characters; the trailers `Rung:` and `Fixture:` for ladder code.

- **`npm run record-sites` and `npm run live` UPLOAD their row unless `JP_NO_REPORT=1`** (skipped only under CI or `REAL_EXTENSION_DIR`): a pre-landing proof run needs it, or it adds a row to /admin/form-filling/lab that nobody can delete. 11 Oct 2026, Ashby: two proof runs uploaded; verified (the log says "1 smoke row(s) sent").
- **A new trace reason must also pass the later-pass filter in `extension/flow.js` (fillTab, "Claude's rows from this pass win")**: it keeps only rows with a Claude source or the PROPOSED reason, so the first pass's "no answer" stayed for a new `written` row, in a replay and live. `worker/test/fill-trace-proposed.test.js` now keeps the two reason words equal. 11 Oct 2026, Ashby motivation question; verified (replay failed until the filter changed).
- **The confirming run can be stopped by the fixture, not the fix:** after the fuller fake applicant (9f6ff67) the AI judged it ineligible for a French role, so the extension did not fill and no field list was read ("reached form, none read"). Say "unconfirmed" and why; do not call it clear. 11 Oct 2026, verified.
- **A fix that changes an ask no longer needs a re-record (14 Oct 2026):** the gate says 🖥 "ask changed" (not worse, not red) and `npm run fill-memo` on the Mac answers only the missed asks and keeps them in the record's `model-memo.json`. `records-publish.mjs` replaces the WHOLE `net-records` release: it needs the fetched full set (no full copy lives on the Mac), `--dry` first. The fill's own proof is a second replay with no model (`fill-memo.mjs` runs it).
- **"On its recording" counts the asks the build makes, not every memo key (cc, 14 Oct 2026):** after a fix reshapes an ask, the old build's answers stay in the memo as the control of every verdict, so the new build never hits them all. `lib/own-asks.mjs` (used by `isSame` and `onRecording`): no extra ask, no site request missing, at least one ask answered. Never prune the memo to make a row "same".
- **A row whose page is an empty shell in the replay made 3 requests, not 120 (14 Oct 2026, Richemont):** count the requests in `JP_NET_LOG` before blaming timing or load. A fulfilled 3xx on a script/fetch/font is not followed by Chromium (an isolated `route.fulfill` test shows it); `lib/net-record.mjs` now follows the recorded chain itself. The "0.55 s vs 7.8 s" gap was the AI's answer time, not a wait.

- **A row red for ONE field: read what the AI said about it before looking at the page.** Greenhouse board form, 15 Oct 2026: the AI had answered "preferred messenger" with value "" and category preference ("applicant must choose"); the worker dropped every empty answer except legal/written/demographic, so the extension traced "no answer in the kit" and the pool called it unexplained. An empty answer of a person-only kind is a held kind row, not a miss. The network replay showed it in one run (reason before/after in out/app.log). Verified.

- **A row red with every left field looking like a hold: run `endingOf` on its record's field list before reading the page.** Migros group site and Denner, 15 Oct 2026: the only required field the ending read as missed was "answered no: left unchecked" (an answer kept); `record-sites.mjs verdictOf` counted it filled but `lib/ending.mjs fieldEnding` did not, so two rows sat on Needs a fix with nothing to fix on the page. Two classifiers of one trace word must share it (`answeredNoOf`). Probe: read the last `fill: fields:` line of the record's app.log into `endingOf` (scratch script, 10 lines). Verified.

- **Second counting artefact in a row (Recruitee form, 15 Oct 2026): a REQUIRED upload slot with "upload: no file for this question" (a motivational letter the app has no file for) fell to `unresolved` in `lib/ending.mjs`, though `record-sites` shortfall ignores file slots.** A document we do not have is `data_missing`, not a missed field. When a row is red with only holds left, run the record's last `fill: fields:` line through `endingOf` first (the probe from the Migros entry). Verified.

## A fix session's plan (20 Oct 2026, internal#9 #22 #23 #36 #37 #38 #40: 7 issues, 1 closed by an earlier PR, 2 declaration fixes, 4 not reproducible; **verified**)
- **Check replayability before the first recording.** Old fill-failure reports (0.9.x builds) carry a host and a label, no snapshot: 3 of 5 open issues could not even make a fixture. Blind recordings of other public postings (3 Ashby, 0 jobs.ch) never had the field. Park such an issue with a comment; reports since #1612 carry the snapshot and the build.
- **Ask every approval the plan needs in one list, first.** Four stalls in one session: a relay without the owner's question, a classifier denial on `gh workflow run`, the owner's decision on the rule itself, the refill. Only a yes typed in this window clears the classifier.
- **A host's daily limit sets the plan:** CI allows 2 visits a host a day across all runs, and a 3-row run on one host used both. Rows 2 and 3 waited hours for 00:00 UTC. Put the rows on different hosts, or run one row per day-slot; never lift the limit.
- **When the AI's category stays wrong after one worked example, go structural at once.** The Public Official dropdown stayed `legal` after a stronger rule and an example (two rounds); the field's type (a select, radio group or dropdown is a choice, a tick is a consent) fixed it. The skill's two-round stop applies: do not try a third wording.
- **A refill on the plan is the cheap proof** (`replay-net.mjs --fill-memo` on a decrypted CI artifact: the record is in the run's `net-records-<run>` artifact, key in Keychain `job-pilotto.capture.key`): minutes, no API spend. It proves what the AI said and what the extension did; "filled from a saved answer" needs a unit test, the replay's fake profile has no saved answers.
- **A new file a replay workflow loads goes in that workflow's `pull_request` paths** or the PR opens red. `tools/pre-push-check.sh` now runs the check for both workflows before the push (`tests/test_pre_push_workflow_paths.py`).

- **Read each field's own reason before the brief's theory.** "a detail of yours not saved yet (first_name)" means the app had NO value to type, not a box that dropped it (27 Oct 2026, Greenhouse: the brief said "names typed but not kept"; the cause was empty Your details, an unconfirmed CV proposal, and a setup draft that dropped the name). Split the fields line by reason first: no value / not kept / not taken are three causes.
- **`ladder-score --spread` ignores `--only`** (27 Oct 2026: "0 fixtures x 3 draws"). For a new fixture's 3 of 3, run `node e2e/ladder-score.mjs --only <id>` three times; the control is one run with the old rung file (`git show origin/main:<file>`).
